# data_seychelles – Seychelles FCAS dispatch model (EPM)

Hourly dispatch model of the Seychelles power system in 2035, used to test whether the fleet can hold the
frequency control / spinning reserve (FCAS) requirement every hour, and at what cost.

- Two zones: **Mahe** and **PraslinLaDigue** (Praslin + La Digue), linked by the planned Mahé–Praslin cable.
- Full chronology: 8,760 hours (`fDispatchMode = 1`), one model year per run, no capacity expansion.
- Unit commitment on: minimum stable load, minimum up/down time, start-up cost.
- FCAS requirement per island, every hour: **N-2 + 10% of solar and wind output**.

> **Do not edit the CSVs by hand.** They are generated by `EPM_SC/epm_inputs/build_epm_inputs.py` from the project
> data in `EPM_SC/` (unit list, demand, solar/wind profiles). Change the builder or its sources, then rebuild.
> Process log and sources: `EPM_SC/_work/WORKLOG.md`. Assumptions for review: `EPM_SC/epm_inputs/Assumptions_for_review.md`.

## How to build and run

```bash
# 1. unit list (only if generator data changed; needs openpyxl for the workbook)
cd EPM_SC/generators && python build_generators.py
# 2. EPM inputs (writes this folder)
cd EPM_SC/epm_inputs && python build_epm_inputs.py
# 3. run from EPM_SC_model/epm (EPM venv / epm_env)
python epm.py --folder_input data_seychelles                    # Baseline (2035) only
python epm.py --folder_input data_seychelles --scenarios        # all scenarios in scenarios.csv
# 4. hourly FCAS balance per island -> <run>/<scenario>/fcas_hourly.csv
python EPM_SC/epm_inputs/analyse_fcas.py <run folder>/baseline
```

Run time for the 2035 Baseline (relaxed, RMIP): about 2–3 minutes, of which CPLEX about 1 minute.

**This folder needs local changes to `epm/base.gms` and `epm/main.gms`** (not on GitHub; see "Model changes" below).

## Key settings (`pSettings.csv`)

| Setting | Value | Meaning |
|---|---|---|
| `fDispatchMode` | 1 | Full 8,760-hour chronology |
| `fEnableCapacityExpansion` | 0 | Fleet is fixed (dispatch only) |
| `fUseSimplifiedDemand` | 0 | Hourly demand read directly from `pDemandData` |
| `fApplyCountrySpinReserveConstraint` | 1 | FCAS requirement per island ("country") |
| `fApplySystemSpinReserveConstraint` | 0 | No combined two-island requirement |
| `sVREForecastErrorPct` | 0.10 | Requirement adds 10% of hourly solar + wind output |
| `sIntercoReserveContributionPct` | 0 | Cable gives no reserve (inactive in EPM anyway) |
| `fApplyIntercoContingency` | 1 | Cable trip: 1 = largest unit + imports, 2 = N-2 + imports (local GAMS setting) |
| `fApplyMinGenCommitment` / `fApplyMUDT` / `fApplyStartupCost` | 1 / 1 / 1 | Unit commitment on |
| `fApplyRampConstraint` | 0 | No ramp limits (engines reach full load within minutes) |
| `fApplyPlanningReserveConstraint` | 0 | No planning-reserve margin (not relevant for dispatch) |
| `VoLL` / `SpinReserveVoLL` | 1,000 / 1,000 | USD per MWh unserved / per MW-hour of reserve shortfall |
| `fEnableInternalExchange` / `fAllowTransferExpansion` | 1 / 0 | Cable used, not expanded |
| `fEnableExternalExchange` | 0 | No external trade |
| `fEnableStorage`, `InitialSOCforBattery` | 1, 0.5 | Batteries on, start/end at 50% charge |
| `CostCurtail` | 0 | No penalty on curtailing solar/wind |

## Assumptions

### FCAS (Deb's method)

| Item | Value | Source |
|---|---|---|
| Requirement, fixed part | **Mahé 2035: largest unit 8 + cable flow 40 = 48 MW**; PLD: two largest 4.5 MW (2025: Mahé 16, PLD 4.9); Islanded: two largest (16 / 4.5) | Deb (15 Oct 2026) |
| Requirement, PLD import | PLD: max(two largest, largest unit 2.5 + import from Mahé) via `fApplyIntercoContingency = 1` | Shen (15 Oct 2026) |
| Requirement, variable part | 10% of hourly solar + wind output (rooftop included) | Deb |
| Thermal capability | `ResLimShare` 0.2 = 20% of unit MW, **only while the unit is on**, within its headroom | Deb; local GAMS change |
| Units with no FCAS | Thermal units **< 6 MW** (all PLD engines, Mahé 2.384 MW remainder), backup/temporary units, **waste-to-energy** | As FCAS_check_2025_2035_SGS.xlsx (Stefania) |
| BESS capability | `ResLimShare` 0.8 = 80% of inverter MW, limited by stored energy | Deb |
| Reserve sharing over the cable | None; each island covers its own requirement | Assumed (conservative) |
| Cable trip as a contingency | Not included | Agreed for now |

## Model changes (local, not on GitHub)

1. **Reserve only from units that are on** – new equation `eSpinningReserveLimOnline` in `base.gms`:
   reserve ≤ Capacity × ResLimShare × isOn. Active only with spinning reserve + dispatch mode + unit commitment, so
   other EPM runs are unaffected.
3. **Interconnector trip as a contingency** – `eSpinningReserveReqIntercoTrip` in `base.gms`, parameter
   `pLargestUnitCountry` (main.gms) and setting `fApplyIntercoContingency` (added to
   `resources/headers/pSettingsHeader.csv`): reserve ≥ largest unit + imports from other countries + 10% VRE.
   Off by default.
2. **Faster unit-commitment equations** – `base.gms` / `main.gms`: lookups `mapAT`, `mapATprev`, `sWinUp`, `sWinDn`
   built once; commitment, min up/down, ramp and storage day-wrap equations use them instead of scanning all hours.
   Same results (validated: identical objective), model build about 100× faster; min up/down time now usable.

4. **Battery and commitment fixes (15 Oct 2026)** – `base.gms`: `eStorInverterLimit` (charge + discharge ≤ MW),
   `eStorEnergyHeadroom` (discharge + reserve ≤ energy stored at the start of the hour), `eStorageSOCInitDispatch` /
   `eStorageSOCFinalDispatch` anchored only at the start/end of the year with the first-hour balance applied (before:
   every month, no balance), `eJointResCapOnline` (output + reserve ≤ MW × on/off status). `generate_report.gms`:
   battery "Charge" and "StateOfCharge" in `pDispatchPlant`.

## Known limitations

- Relaxed commitment (RMIP) lets units run partly on, e.g. tiny output slices that still offer reserve. MIP not yet tested.
- N-2 is fixed per year (installed units), not the two largest units online in each hour.
- The cable gives no reserve; its trip is covered by the fixed 40 MW in the Mahé requirement (applied every hour, even when the cable carries less).
- Inputs changed on 14 Oct 2026 (aligned with Stefania); runs before that date used the earlier assumptions.
- Demand shape is synthetic; no PUC hourly data.
- Fuel prices flat at 2024 levels; commitment parameters generic.
